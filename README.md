## 📖 项目介绍

禁止商用与倒卖。

在自己的电脑上运行游戏服务，体验剧情、战斗、角色养成与抽卡，并将进度保存在本地 PostgreSQL 数据库中。启动器统一管理环境配置、服务启动、游戏接入和运行日志，首次本地登录自动创建账号与存档。

界面基于 Python 与 Qt，支持日间、夜间模式。当前启动器版本为 **0.1.0**。

大量Vibe Coding，使用GPT-3.1 Sol，大概消耗三个5小时额度。

## 🚀 快速开始

### 1. 准备运行环境

| 需要准备 | 说明 |
| --- | --- |
| Windows x64 | 当前面向 Windows 台服 PC 客户端 |
| 完整游戏客户端 | 从 [台服官网](https://shadow.softstargames.com.tw/download) 下载 Windows 版本，并完成正常资源下载 |
| Python | 安装 **64 位 Python 3.10–3.14**，可从 [Python 官网](https://www.python.org/downloads/windows/) 获取 |
| PostgreSQL | 从 [PostgreSQL 官网](https://www.postgresql.org/download/windows/) 安装；启动器自动查找已安装的数据库程序 |
| mitmproxy | 从 [mitmproxy 官网](https://www.mitmproxy.org/) 获取 Windows 工具，设置时选择其中的 `mitmweb.exe` |

首次准备需要联网安装 Python 依赖。客户端安装、资源下载及第三方登录也可能需要网络；如果当前网络无法访问相关服务，请先解决网络连接问题。本地游戏 API 由本机服务处理。

启动器会自动准备独立 Python 环境和依赖；Python、PostgreSQL 本体以及游戏客户端、接入工具需要自行安装或准备。

### 2. 打开启动器并完成配置

1. 将项目放在可写目录，双击根目录的 **`MasterofGarden.cmd`**。
2. 打开 **「设置」**，选择游戏入口 `MasterofGarden.exe` 和接入工具 `mitmweb.exe`。
3. 确认数据库名称、用户名和端口。默认使用独立数据库 `MogLocalOpenSource`，已有数据库服务须填写正确密码。
4. 点击 **「一键完成配置」**，确认要使用的目标数据库。启动器会保存设置、准备依赖、更新服务配置，并创建数据库及应用迁移。
5. 到 **「环境准备」** 查看检查结果。处理阻塞项后，在 **「开始游戏」** 页启动游戏。

指定端口没有服务、且尚未创建项目数据库实例时，启动器会利用已安装的 PostgreSQL 创建本项目实例。新实例可自动生成密码，保存后立即回填设置页；勾选 **「显示密码」** 即可查看，配置失败后也会保留。

首次启动时，接入工具会生成本项目的代理证书。启动器检查并在需要时安装到 **当前 Windows 用户的受信任根证书存储**，验证通过后才打开游戏；失败原因可在运行日志中查看。

### 3. 按需启用本地支付

需要体验本地充值或商品入库时，先退出游戏，在设置页的 **「客户端 DLL」** 区域点击 **「修改 DLL」**。补丁会备份所选游戏目录中的 `GameAssembly.dll`，再对已适配版本进行修改；此流程不涉及真实货币交易。

需要还原时点击 **「恢复 DLL」**。请保留 `GameAssembly.dll.before-local-payment.bak` 备份文件；恢复 DLL 不会回退本地玩家存档。客户端版本不匹配时会拒绝修改。

## ✨ 已实现功能

### 游戏体验

- **本地账号与存档**：首次登录自动创建本地玩家，进度持久化保存，服务重启后继续使用。
- **抽卡与奖励**：提供卡池、普通抽卡、箱式抽奖、任务、邮件／礼物箱及通行证相关功能。
- **剧情与推关**：提供关卡推进、战斗结算、剧情阅读与回顾；包含教学关卡阵容及结算适配。
- **角色与编成**：提供角色养成、队伍编成、技能树节点解锁及相关道具操作。
- **主页与日常**：提供自身资料、主页、聊天、背包物品使用与秘密基地相关功能。
- **其他玩法**：包含挑战之塔、超次元世界树等玩法的本地实现。
- **本地数据管理**：可以编辑自己的金币、幻魔石和普通道具余额。

### 启动器

- **一键配置**：自动准备独立 Python 环境、安装依赖、生成服务配置并初始化数据库。
- **一键启动与停止**：管理当前窗口启动的本地服务、接入工具和游戏进程，失败时回收本轮新增进程。
- **环境检查**：检查文件、依赖、配置、端口以及数据库认证、结构与迁移状态。
- **运行状态**：查看组件状态、进程和端口占用；可选择并确认关闭占用程序。
- **运行日志**：切换查看服务端、接入、数据库初始化及后台错误等日志，支持自动更新和跟随滚动。
- **本机设置**：保存路径、数据库密码与端口；支持日夜模式、DLL 修改／恢复和许可全文查看。

## 💡 常见问题

### 启动器打不开，提示缺少 Python？

请确认已经安装受支持的 64 位 Python，再重新双击 `MasterofGarden.cmd`。启动入口会自动查找解释器，无需在设置中选择 Python 路径。

依赖安装失败时先检查网络与目录权限。服务端解释器失效后，一键配置会保留旧环境副本并重建；已经生成的配置和存档需要继续保留。

### 数据库密码在哪里查看？

打开设置页，勾选数据库密码旁的 **「显示密码」**。新实例自动生成的密码会立即回填，后续配置失败也不会清空。

密码使用当前 Windows 用户的 DPAPI 加密保存。清空密码框后点击「保存设置」会删除已保存密码，之后可通过 `MOG_DB_PASSWORD` 环境变量提供密码；已有实例的密码不会因此改变。

设置或密码读取失败时，启动器会暂停数据库自动恢复。请先确认连接信息并保存，再重新配置。

### 端口已被占用怎么办？

在首页查看占用程序，按需修改设置中的端口，或通过 **「关闭程序」** 确认关闭目标。默认端口为 API `18180`、本地接入 `18181`、接入管理 `18182`、数据库 `5432`。

关闭数据库会断开整个实例的连接；使用其他程序正在连接的数据库时，请先确认影响。普通「停止本次启动」只停止当前窗口管理的游戏、接入和服务进程，项目数据库实例会继续运行。

### 检查通过，但仍然无法进入游戏？

环境检查通过表示所需文件、依赖和数据库等检查已满足；客户端登录、资源加载与进入场景仍需以实际游戏画面为准。

先确认台服 PC 客户端已正常下载资源，再到 **「运行日志」** 查看服务端和接入输出。出现 `local_resource_catalog_missing` 时，请检查客户端资源是否下载完成；本项目不会代替客户端下载或修复游戏资源。

### 如何修改金币、幻魔石和道具？

可使用 pgAdmin、DBeaver 或 psql 连接自己的本地数据库，先退出游戏并停止本地服务，再按 [数据库修改说明](docs/database-editing.md) 查询玩家和修改余额。GM 界面暂未提供这些操作。

### 更新项目时怎样保留存档？

先停止游戏和本地服务，备份数据库，再更新代码。保留自己的 **`runtime/`、游戏目录和 PostgreSQL 数据库**；外部数据库的存档位于对应实例，不一定在项目目录中。

更新后重新打开启动器，检查环境并按需完成配置。数据库结构更新后的回退需要对应的数据库备份，单纯替换旧代码无法还原存档结构。
